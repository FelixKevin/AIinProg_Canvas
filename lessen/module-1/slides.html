Waar komt de kennis vandaan?

Een LLM wordt in fases getraind

1 · Pretraining

Voorspel het volgende token, op enorme hoeveelheden tekst. Het model leert taal, feiten en code.
→

2 · Fine-tuning

Het traint verder op goede gesprekken. Mensen beoordelen antwoorden. Het leert zich gedragen als assistent.
→

3 · Knowledge cutoff

De training stopt. Het model verandert niet meer.

4 · In gebruik

De grote vraag

Begrijpt een LLM wat het schrijft?

Om goed te voorspellen hoe code verdergaat, moet het model leren hoe code werkt.

Zulke geleerde patronen zijn abstractions: algemene ideeën, die het ook toepast op situaties die het nooit zag.

Is dat “begrijpen”? Daarover zijn experts het niet eens.

wat wel vaststaat
Geen database. Het zoekt geen antwoorden op, het maakt ze.
Geen rekenmachine. Het volgt geen vaste regels.
Elk antwoord is een voorspelling, met een kans om fout te zijn.
Deterministic of niet

Een LLM is geen rekenmachine

Rekenmachine

Volgt vaste regels. 1 + 1 = 2, altijd.
Deterministic: dezelfde input geeft altijd dezelfde output.

LLM

Voorspelt het antwoord. 2 + 2 zag het miljoenen keren. Een grote som moet het stap voor stap opbouwen. En dan kan het zich vergissen, net als jij.
48 271 × 9 314 = 449 596 094

Hoe rekenen AI-tools dan wel juist? Het model schrijft code, en een programma voert die uit.

Wat doet een agent harness?

Vier dingen

Je vraag naar het model sturen, met extra informatie: open bestanden, een foutmelding.
Het model een lijst van tools geven: bestand lezen, bestand schrijven, commando uitvoeren, zoeken.
De tool uitvoeren die het model kiest, en het resultaat teruggeven.
Een afbeelding doorgeven aan een model dat afbeeldingen kan lezen.
Zo werkt het

De tool loop

Jij“Los de test op die faalt in cart.js.”
Model(tekst) “Gebruik tool read_file op cart.js.”
Agent harnessleest cart.js en geeft de inhoud aan het model.
Model(tekst) “Gebruik tool run_command: npm test.”
Agent harnessvoert npm test uit en geeft de output aan het model.
Model(tekst) “Gebruik tool write_file: verander regel 8 in …”
Agent harnesspast het bestand aan. En zo verder, tot het model zegt dat het klaar is.

Het model schrijft nog altijd alleen tekst. De agent harness doet het echte werk.

Beperking 1

Hallucinations

Je vraagt een npm-package voor een taak. Je krijgt een naam, een installatiecommando en een codevoorbeeld.

Je installeert. npm vindt de package niet. Ze bestaat niet.

Hallucination: output die er correct uitziet, maar verzonnen is.
Let op. Soms bestaat de verzonnen naam wél. Kwaadwillige mensen registreren namen die AI-modellen vaak verzinnen, met schadelijke code erin.

1.7

Quality control

AI-output is onbewezen.
Je vraagt: controleer of een e-mailadres geldig is

De code werkt. Maar klopt ze?

def is_valid_email(address):
    return "@" in address and "." in address

print(is_valid_email("sara.elamrani@example.com"))
print(is_valid_email("@."))
True
True

@. is geen e-mailadres. Toch zegt de function True.

Quality control (QC): je controleert elke AI-output voor je ze gebruikt. Dat is nooit optioneel.
QC

Vijf stappen

Verifieer de correctheid. Voer de code uit en test ze. Ook als ze logisch lijkt.
Analyseer de aannames. Waarom staat dit er zo? Bleef het model binnen je vraag?
Controleer de consistentie met je codebase: namen, mappen, patronen.
Beschouw de output als onbewezen, tot jouw controle het tegendeel aantoont.
Werk in kleine stappen. Genereer, test, pas aan, integreer. Dan pas verder.
De test
Kan je een stuk AI-code niet uitleggen aan een medestudent? Dan is het nog niet klaar voor je project.
